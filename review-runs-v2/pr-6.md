# Code Review: PR-6

Висновок: BLOCK

Знайдені проблеми:

- [blocker] [INPUT-01] [confirmed defect] `app/src/imports.js:22-24` (diff)
  Доказ: кожен рядок після заголовка без будь-якої перевірки розбирається як `name,email,phone`, а потім безумовно додається до `db.members`. Порожній файл/рядок, неповний рядок або зайві поля не відхиляються; значення можуть бути `undefined` або порожніми, а коми всередині CSV-поля розбивають запис неправильно. Наслідок: імпорт пошкоджених або навмисно malformed даних створює некоректних учасників і змінює стан частково обробленого імпорту. Виправлення: використати явний CSV-парсер або обмежений парсер із підтримкою quoting, перевіряти заголовок, точну кількість полів, обов’язкові непорожні значення та формат email/phone до будь-якого `push`; відхиляти весь файл або мати чітко визначену транзакційну семантику.

- [blocker] [AUTH-01] [confirmed defect] `app/src/imports.js:17-18` (diff)
  Доказ: `fileName` без валідації передається до `path.join(uploadDir, fileName)`. Значення з `..` може вийти за межі `uploadDir`, тому admin може змусити функцію читати довільний доступний файл, трактувати його вміст як CSV і записати результат у базу. Перевірка ролі сама по собі не обмежує ресурс, до якого надається доступ. Наслідок: порушення меж завантажень та імпорт даних із несанкціонованого шляху. Виправлення: приймати лише базове ім’я файлу (відхиляти абсолютні шляхи й сегменти `..`), канонізувати шлях і перевіряти, що він залишається всередині канонізованого `uploadDir`; також перевірити існування та тип звичайного файлу.

- [minor] [ID-01] [risk to verify] `app/src/imports.js:23` (diff)
  Доказ: ID генерується як `db.members.length + 1`, без перевірки зайнятості ID. У поточному seed це дає 6, але після видалення, імпорту або іншої зміни колекції довжина не є гарантією вільного і стабільного ідентифікатора. Наслідок: можливі дублікати ID та неправильні `findMember`/зв’язки. Потрібно перевірити сценарій імпорту після видалення або часткового відновлення даних; виправлення — окремий монотонний лічильник/генератор ID у `db`.

Автоматичні перевірки:

- `cd app && npm test` — не запускався: у середовищі PowerShell виконання `npm.ps1` заборонене політикою ExecutionPolicy. PR було застосовано для підготовки перевірки, але команду тестів виконати не вдалося; зміни після цього прибрано з `app/`.

Підсумок: PR блокується двома підтвердженими дефектами: небезпечним доступом за шляхом і відсутністю валідації CSV-входу. Доданий тест перевіряє лише щасливий шлях та роль admin/librarian і не покриває traversal, malformed CSV, частковий імпорт або стабільність ID.
