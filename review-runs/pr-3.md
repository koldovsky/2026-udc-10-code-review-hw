### 1. [critical] Будь-який учасник може вивантажити email і телефони всіх учасників — правило 1 (також 10)
- **Де:** `app/src/members.js:12`
- **Цитата:**
  ```js
  export function exportMembersCsv(db, user) {
    if (!user) throw new AccessDenied();
  ```
- **Чому це проблема:** сусідня `listMembers` віддає лише імена й ролі, і то тільки персоналу (`requireRole(user, STAFF)`). `memberCard` дає звичайному учаснику лише його власну картку. Нова функція перевіряє тільки, що користувач є, тож учасник з `role: "member"` отримує контакти всієї громади. Це витік персональних даних. Фраза в PR.md «як і скрізь» приховує, що перевірка слабша, ніж у сусідніх функціях.
- **Як виправити:** замінити рядок на `requireRole(user, STAFF);`, як у `listMembers`.

### 2. [high] Експорт персональних даних не пише журнал доступу — правило 2
- **Де:** `app/src/members.js:14`
- **Цитата:**
  ```js
  const lines = db.members.map((m) => [m.id, m.name, m.email, m.phone, m.role].join(","));
  ```
- **Чому це проблема:** функція повертає email і телефон кожного учасника, але не викликає `logAccess`. Після експорту на питання «хто і навіщо дивився мої дані» відповіді немає. `memberCard` у цьому ж модулі журнал пише.
- **Як виправити:** для кожного учасника в експорті викликати `logAccess(db, user, m.id, "members-export")`. Додати тест, що `db.accessLog` містить рівно один запис на кожного учасника з правильними `by` і `purpose`.

### 3. [medium] Тести не перевіряють відмову для учасника без прав і не перевіряють вміст рядків — правило 9 (також 8, 10)
- **Де:** `app/test/members.test.js:36`
- **Цитата:**
  ```js
  test("CSV export has a header and one row per member", () => {
    const csv = exportMembersCsv(createDb(), iryna);
    const lines = csv.split("\n");
    assert.equal(lines[0], "id,name,email,phone,role");
    assert.equal(lines.length, 6);
  });

  test("CSV export refuses an anonymous caller", () => {
    assert.throws(() => exportMembersCsv(createDb(), null), AccessDenied);
  });
  ```
- **Чому це проблема:** відмову перевірено лише для анонімного виклику. Немає тесту, що учасник з `role: "member"` (наприклад, `olya`) отримує `AccessDenied`, тому дефект #1 тести не ловлять. «Тест на формат» перевіряє тільки заголовок і кількість рядків, а не значення в жодному рядку.
- **Як виправити:** додати `assert.throws(() => exportMembersCsv(createDb(), olya), AccessDenied)`. Перевірити хоча б один рядок повністю, наприклад `assert.equal(lines[1], "1,Оля Приклад,olya@example.invalid,+380000000001,member")`.

### 4. [medium] Поля в CSV не екрануються — правило 15
- **Де:** `app/src/members.js:14`
- **Цитата:**
  ```js
  const lines = db.members.map((m) => [m.id, m.name, m.email, m.phone, m.role].join(","));
  ```
- **Чому це проблема:** якщо ім'я містить кому, лапки або перенос рядка (наприклад, «Приклад, Оля»), колонки зсуваються, і звірка дає неправильний результат. Значення, що починаються з `=`, `+`, `-` чи `@`, табличні редактори виконують як формулу (CSV injection). Телефони тут починаються з `+`.
- **Як виправити:** брати кожне поле в лапки і подвоювати внутрішні `"` (`'"' + String(v ?? "").replace(/"/g, '""') + '"'`). Для захисту від формул додавати `'` перед значеннями, що починаються з `= + - @`, або задокументувати, що клієнт має відкривати файл як текст. Додати тест з комою та лапками в імені.

### 5. [medium] Експорт віддає всіх учасників одним списком, без сторінок — правило 7
- **Де:** `app/src/members.js:14`
- **Цитата:**
  ```js
  const lines = db.members.map((m) => [m.id, m.name, m.email, m.phone, m.role].join(","));
  return [header, ...lines].join("\n");
  ```
- **Чому це проблема:** кількість учасників з часом росте без меж, а функція віддає їх усіх одним рядком. Ризик поки вузький, бо громада невелика, але правило порушено.
- **Як виправити:** додати параметри `{ page, pageSize }` з обмеженим максимумом, як вимагає правило 7. Інакше погодити з командою окремий виняток для експорту і задокументувати його.
