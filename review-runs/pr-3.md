# Рев'ю: pr-3

**Вердикт:** BLOCK

## Знахідки

### Правило 1 — Перевірка ролі — violation (blocking, critical)

`exportMembersCsv` перевіряє лише наявність користувача, тоді як сусідня `listMembers` (дзеркальний «довідник» учасників) вимагає `requireRole(user, STAFF)`, а `memberCard` дозволяє не-staff бачити лише власну картку. Тож нова функція має слабшу перевірку, ніж сусіди, і при цьому віддає більше даних.

- **Де:** `app/src/members.js`, функція `exportMembersCsv`, перший рядок тіла
- **Сценарій:** звичайний учасник `{ id: 1, role: "member" }` викликає `exportMembersCsv(db, olya)` → отримує email і телефон усіх 5 учасників замість `AccessDenied` (для порівняння, `listMembers(db, olya)` кидає `AccessDenied`). Тесту, що учасника з роллю `member` відхилено, немає — є лише тест на анонімного.

> ```
> +export function exportMembersCsv(db, user) {
> +  if (!user) throw new AccessDenied();
> ```

### Правило 2 — Журнал доступу до ПД — violation (blocking, critical)

Функція віддає email і телефон кожного учасника, але жодного разу не викликає `logAccess`, хоча має бути один запис на кожного учасника в циклі (як у `memberCard`).

- **Де:** `app/src/members.js`, `exportMembersCsv`, рядок з `db.members.map(...)`
- **Сценарій:** staff `{ id: 3, role: "librarian" }` викликає `exportMembersCsv(db, iryna)` → у CSV є email/телефон 5 учасників, а `db.accessLog` лишається `[]` замість 5 записів `[3, memberId, "<purpose>"]`.

> ```
> +  const lines = db.members.map((m) => [m.id, m.name, m.email, m.phone, m.role].join(","));
> +  return [header, ...lines].join("\n");
> ```

### Правило 12 — Коректність логіки — violation (blocking, high)

Значення з'єднуються через `join(",")` без екранування за CSV (лапки для полів із `,`, `"`, переносом рядка), тому вивід неправильний для цілком реальних даних.

- **Де:** `app/src/members.js`, `exportMembersCsv`, рядок з `.join(",")`
- **Сценарій:** учасник з `name: "Петренко, Іван"` → рядок `6,Петренко, Іван,ivan@…,+380…,member` має 6 колонок замість 5: email потрапляє в колонку `email` зі зсувом, телефон — у `role`; ім'я з `\n` розриває один запис на два рядки, і `lines.length` перестає дорівнювати кількості учасників.

> ```
> +  const lines = db.members.map((m) => [m.id, m.name, m.email, m.phone, m.role].join(","));
> ```

### Правило 7 — Пагінація — violation (blocking, medium)

Функція повертає всіх учасників одним рядком без сторінок і без обмеження розміру, а список учасників може рости без меж.

- **Де:** `app/src/members.js`, `exportMembersCsv`
- **Сценарій:** у громаді 100 000 учасників → один виклик формує в пам'яті CSV на весь реєстр; клієнт не може (і не мусить) обмежити розмір відповіді, немає параметрів `limit`/`offset` з максимумом.

> ```
> +  const lines = db.members.map((m) => [m.id, m.name, m.email, m.phone, m.role].join(","));
> ```

### Правило 13 — Мінімум даних у відповіді — pass

Набір полів (ім'я, email, телефон, роль + `id`) відповідає заявленій меті звірки з громадою; весь об'єкт учасника (`...m`) не віддається. Проблема — у тому, кому і без журналу ці дані віддаються (правила 1, 2), а не в наборі полів.

- **Де:** `app/src/members.js`, `exportMembersCsv`

> Для щомісячної звірки з громадою потрібен експорт учасників у CSV: ім'я, email, телефон, роль.
