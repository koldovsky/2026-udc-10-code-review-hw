# Рев’ю PR-2

Виявлено 3 проблеми.

1. **Критичність: high**  
   **Правило:** повернення email або телефону має журналюватися через `logAccess` для кожного учасника.  
   **Файл і рядок diff:** `app/src/loans.js:55`  
   **Умова:** бібліотекар або адміністратор успішно викликає `overdueReport`, і в звіті є учасник із простроченою позикою.  
   **Наслідок:** звіт повертає email учасника без запису в журналі доступу, тож неможливо перевірити, хто читав ці персональні дані.  
   **Напрям виправлення:** журналювати доступ до email кожного учасника, чий email повертається, і додати тест на відповідні записи в `accessLog`.

2. **Критичність: medium**  
   **Правило:** API передає грошові суми цілими копійками.  
   **Файл і рядок diff:** `app/src/loans.js:59`  
   **Умова:** `overdueReport` повертає рядок із простроченою позикою.  
   **Наслідок:** API додає форматоване текстове представлення суми (`feeText`) поруч із цілим значенням `feeKopecks`; клієнти можуть почати залежати від текстового формату та його розділювача.  
   **Напрям виправлення:** залишити суму в API цілим числом копійок, а форматування для показу виконувати на рівні представлення.

3. **Критичність: low**  
   **Правило:** зміни публічного API мають бути відображені в `app/CHANGELOG.md`.  
   **Файл і рядок diff:** `app/src/loans.js:55` і `app/src/loans.js:59`  
   **Умова:** PR додає до результату `overdueReport` поля `email` і `feeText`.  
   **Наслідок:** опис публічного контракту в changelog не відповідає новій формі результату.  
   **Напрям виправлення:** оновити changelog, зазначивши додані поля, або прибрати поле, яке не має бути частиною API.
