# Рев'ю pr-2: Email учасника у звіті про прострочення

**Вердикт:** BLOCK
**Модель / інструмент:** GitHub Copilot (JetBrains, agent mode), промпт `review/prompt.md`; рев'ю виконано в спільній сесії агента послідовно, по одному PR (окремі нові сесії інструмент не дозволив запустити)

## Що заявляє PR
Додає email учасника в кожен рядок staff-only звіту `overdueReport`, щоб бібліотекарі одразу писали нагадування.
- «Тепер для кожного рядка беремо учасника і віддаємо ім'я та email»
- «Звіт і так лише для персоналу, тож email тут доречний»
- (неявно) інших змін немає

## Знахідки

### 1. [high] [R2] Email віддається без запису в журнал доступу
- **Де:** `app/src/loans.js:+55` (диф, рядок 16)
- **Цитата:** `email: db.findMember(l.memberId)?.email ?? null,`
- **Чому це проблема:** домовленість 2: функція, що повертає email, викликає `logAccess(db, user, memberId, purpose)` — по одному запису на кожного учасника, чиї дані віддано. Перевірено з застосованим дифом: `overdueReport(db, librarian, "2026-10-08")` віддає 3 рядки з email, а `db.accessLog.length === 0`. Те, що звіт staff-only, не звільняє від журналу — `memberCard` теж доступний персоналу і пише журнал. Це дає масове вивантаження контактів без сліду.
- **Як виправити:** імпортувати `logAccess` з `./audit.js` і для кожного **унікального** `memberId` у результаті викликати `logAccess(db, user, memberId, "overdue-report")`; тест, що перевіряє вміст `db.accessLog`.
- **Впевненість:** висока

### 2. [high] [R4] Форматування грошей для людей у `src/`
- **Де:** `app/src/loans.js:+59` (диф, рядок 20)
- **Цитата:** `feeText: (lateFee(l, todayIso) / 100).toFixed(2).replace(".", ",") + " грн",`
- **Чому це проблема:** домовленість 4: гроші в API лише цілими копійками, форматування («15,00 грн») робить клієнт, а не `src/`. З дифом: `feeText: "110,00 грн"`.
- **Як виправити:** прибрати `feeText`; клієнт форматує `feeKopecks`.
- **Впевненість:** висока

### 3. [high] [R10] Опис PR не згадує нове поле `feeText`
- **Де:** PR.md; `app/src/loans.js:+59` (диф, рядок 20)
- **Цитата:** опис: «віддаємо ім'я та email»; код: `feeText: (lateFee(l, todayIso) / 100)…`
- **Чому це проблема:** опис має відповідати коду. Зміна, якої немає в описі, проходить повз рев'ю за наміром і порушує R4.
- **Як виправити:** прибрати `feeText` (див. знахідку 2) або винести в окремий PR з обґрунтуванням.
- **Впевненість:** висока

### 4. [high] [R6] Зміна результату публічної функції без запису в `app/CHANGELOG.md`
- **Де:** `app/src/loans.js` (диф, рядки 16, 20); `app/CHANGELOG.md` у дифі не змінено
- **Цитата:** `email: …`, `feeText: …`
- **Чому це проблема:** `overdueReport` повертає нові поля (`email`, `feeText`) — це зміна контракту, а в CHANGELOG вона не описана; у записі 2026-09 перелік полів тепер неточний.
- **Як виправити:** запис у CHANGELOG: «`overdueReport` додає `email`; кожен рядок записується в журнал доступу».
- **Впевненість:** висока

### 5. [medium] [R8] Тест не перевіряє журнал доступу і нові поля повністю
- **Де:** `app/test/loans.test.js:+48` (диф, рядок 32)
- **Цитата:** `assert.equal(rows[0].email, "marko@example.invalid");`
- **Чому це проблема:** перевірено лише email першого рядка; немає перевірки `db.accessLog` (знахідка 1 пройшла б з тестами зеленими — з дифом 13/13), немає перевірки, що для учасника без запису `email === null`.
- **Як виправити:** `assert.deepEqual(db.accessLog.map((e) => [e.by, e.memberId, e.purpose]), [[3, 5, "overdue-report"], [3, 2, "overdue-report"], [3, 1, "overdue-report"]])` (або за обраною семантикою унікальності).
- **Впевненість:** висока

### 6. [medium] [R7] Звіт — безмежний список, тепер ще й з персональними даними
- **Де:** `app/src/loans.js` (`overdueReport`, диф, рядки 10–22)
- **Цитата:** `return db.loans.filter((l) => l.returnedAt === null && l.dueAt < todayIso)`
- **Чому це проблема:** кількість прострочених позик не обмежена; без сторінкування один виклик вивантажує всі email боржників. Проблема існувала й до PR, але PR збільшує ризик.
- **Як виправити:** сторінкування з обмеженим `pageSize` (окремим PR або тут, якщо команда вирішить).
- **Впевненість:** середня

### 7. [low] [R18] Повторні обчислення в кожному рядку
- **Де:** `app/src/loans.js` (диф, рядки 15–16, 19–20)
- **Цитата:** `db.findMember(l.memberId)?.name` / `db.findMember(l.memberId)?.email`; `lateFee(l, todayIso)` двічі
- **Чому це проблема:** `findMember` — лінійний пошук, викликається двічі на рядок (раніше — одна `Map`); дрібниця з продуктивності й читабельності.
- **Як виправити:** `const m = db.findMember(l.memberId);` або повернути `Map` за id.
- **Впевненість:** висока
