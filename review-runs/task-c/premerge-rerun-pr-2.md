## Знахідки

### [P1] Email повертається без запису в журнал доступу

- **Правило:** функція, що повертає email або телефон учасника, має викликати `logAccess`.
- **Файл/рядок diff:** `app/src/loans.js:54` — додане поле `email`.
- **Умова:** щоразу, коли викликають `overdueReport` і звіт містить учасника, функція повертає його email, але не записує доступ до журналу.
- **Наслідок:** читання персональних даних через звіт не можна відстежити.
- **Напрям виправлення:** викликати `logAccess` для кожного учасника, чий email повертається, із відповідним користувачем і метою доступу.

### [P2] Повторний лінійний пошук учасника для кожної простроченої позики

- **Правило:** уникати повторних лінійних пошуків усередині циклів, що дають квадратичну складність.
- **Файл/рядки diff:** `app/src/loans.js:53–54` — два виклики `db.findMember(...)` у побудові кожного рядка звіту. У базовому коді `findMember` використовує `members.find(...)`.
- **Умова:** для кожної простроченої позики пошук перебирає масив учасників двічі.
- **Наслідок:** зі зростанням кількості позик і учасників побудова звіту масштабується як O(позики × учасники).
- **Напрям виправлення:** побудувати індекс учасників один раз перед обробкою позик або виконувати один пошук на позику й повторно використовувати знайдений запис.

### [P3] Додане форматоване поле суми не описане в PR

- **Правило:** зміни мають відповідати опису PR.
- **Файл/рядок diff:** `app/src/loans.js:58` — додане поле `feeText`.
- **Умова:** опис PR обіцяє ім’я та email у звіті, але не згадує нове поле з відформатованою сумою.
- **Наслідок:** зміна публічного формату звіту може стати несподіванкою для споживачів і рецензентів.
- **Напрям виправлення:** оновити опис PR, щоб він охоплював `feeText`, або прибрати поле, якщо воно не входить у цю зміну.

### [P3] Нове поле `feeText` не перевіряється тестом

- **Правило:** нова поведінка має мати конкретний тест; грошові значення слід представляти цілими копійками.

- **Умова:** поле форматує суму з копійок у текст, однак доданий тест перевіряє лише числову суму.
- **Наслідок:** тест не виявить помилку в десятковому роздільнику, кількості знаків після коми чи суфіксі валюти.
- **Напрям виправлення:** додати перевірку очікуваного `feeText` для суми з копійками.
