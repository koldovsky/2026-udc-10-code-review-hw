## Знахідки

### 1. [high] Off-by-one: при `page = 1` пропускається перша сторінка — правило 15 (також 10)
- **Де:** `app/src/loans.js:32`
- **Цитата:**
  ```js
  export function listLoansPage(db, user, { page = 1, pageSize = 20 } = {}) {
    const all = listLoans(db, user);
    const start = page * pageSize;
  ```
- **Чому це проблема:** Сторінки нумеруються з 1 (`page = 1` за замовчуванням), а зсув рахується як `page * pageSize`. Тому сторінка 1 починається з рядка 20, а рядки 0–19 не видно на жодній сторінці. На тестових даних (7 позик) `listLoansPage(db, iryna)` повертає `items: []` при `total: 7`. Значення `page` ≤ 0 чи нечислові теж ніяк не перевіряються: `page = -1` дає від'ємний `start`, і `slice` повертає хвіст масиву.
- **Як виправити:** `const start = (page - 1) * pageSize;`. Перед цим перевірити, що `page` — ціле число ≥ 1: інакше кидати помилку або підставляти 1.

### 2. [medium] Розмір сторінки від клієнта не обрізається — правило 7
- **Де:** `app/src/loans.js:30`
- **Цитата:**
  ```js
  export function listLoansPage(db, user, { page = 1, pageSize = 20 } = {}) {
  ```
- **Чому це проблема:** Список позик росте без меж (у PR 3 000+ рядків) і віддається інтерактивному UI. Сторінковість тут є, але `pageSize` береться від клієнта як є: `pageSize: 1e6` поверне весь список, і вся користь від сторінок зникає. Нуль чи від'ємне значення дасть порожню або невизначену сторінку.

### 3. [high] Тест не перевіряє вміст сторінки — правило 8 (також 10)

Тому тест зелений, хоча перша сторінка порожня (#1). Твердження PR «Тест додав» формально правдиве, але сторінкування цей тест не покриває.
- **Як виправити:** Перевіряти `items` явно. Наприклад, `{ page: 1, pageSize: 3 }` → `res.items.map(l => l.id)` дорівнює `[1, 2, 3]`; `{ page: 3, pageSize: 3 }` → `[7]`. Додати перевірку обрізання великого `pageSize`.
