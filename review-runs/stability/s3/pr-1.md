## Знахідки

### 1. [high] Off-by-one: сторінка 1 (за замовчуванням) пропускає перші `pageSize` позик — правило 15 (також 8, 10)
- **Де:** `app/src/loans.js:32`
- **Цитата:**
  ```js
  export function listLoansPage(db, user, { page = 1, pageSize = 20 } = {}) {
    const all = listLoans(db, user);
    const start = page * pageSize;
  ```
- **Чому це проблема:** За замовчуванням `page = 1`, тобто нумерація з 1, а зсув рахується як для нумерації з 0. Тому `page: 1` повертає рядки 20–39, а перших 20 позик клієнт не отримає з жодної сторінки. На тестовій базі (7 позик) виклик із тесту повертає `items: []` при `total: 7`. Тест перевіряє лише `total`, `page` і `pageSize`, які функція просто повертає назад, а `items` не дивиться. Тому тест проходить і баг не ловить. Перевірка значень, які функція лише повертає назад, — не перевірка результату (правило 8).
- **Як виправити:** `const start = (page - 1) * pageSize;`. У тесті перевіряти конкретні id: `assert.deepEqual(res.items.map((l) => l.id), [1, 2, 3, 4, 5, 6, 7])` для `page: 1`. Додати випадок на кілька сторінок, наприклад `pageSize: 3, page: 3` → `[7]`, і сторінку за межами → `[]`.

### 2. [medium] Розмір сторінки не обмежено і не перевіряється — правило 7 (також 15)

- **Цитата:**
  ```js

  ```
- **Чому це проблема:** Правило 7 вимагає, щоб у сторінковому списку максимальний розмір сторінки обрізався. Тут `pageSize` від клієнта береться як є: `{ pageSize: 1e9 }` віддає всі 3 000+ рядків, тобто ту саму проблему, яку PR мав прибрати. `page`/`pageSize`, що дорівнюють 0, від'ємні чи не цілі, не відхиляються: `pageSize: 0` мовчки дає порожню сторінку, а від'ємний `start` у `slice` рахується з кінця масиву.
