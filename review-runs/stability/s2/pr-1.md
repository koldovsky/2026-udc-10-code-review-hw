## Знахідки

### 1. [high] Off-by-one: `page = 1` пропускає першу сторінку — правило 15 (також 10)
- **Де:** `app/src/loans.js:32`
- **Цитата:**
  ```js
  export function listLoansPage(db, user, { page = 1, pageSize = 20 } = {}) {
    const all = listLoans(db, user);
    const start = page * pageSize;
  ```
- **Чому це проблема:** За замовчуванням сторінки рахуються з 1, а зсув обчислюється як для нумерації з 0. Тому виклик за замовчуванням (`page: 1`) починає з рядка 20, і перші 20 позик ніколи не повертаються. На тестовій базі (7 позик) `page: 1` повертає `items: []` при `total: 7`. Значення `page` ≤ 0, дробові чи `NaN` теж ніяк не перевіряються: від'ємний `start` у `slice` рахує рядки з кінця масиву.
- **Як виправити:** `const start = (page - 1) * pageSize;`. Перевіряти, що `page` — ціле число ≥ 1, інакше кидати помилку або приводити до 1.

### 2. [medium] Розмір сторінки не обрізається — правило 7

- **Цитата:**
  ```js

  ```
- **Чому це проблема:** Клієнт може передати `pageSize: 1e9` і отримати всі 3 000+ рядків за один запит, тож сторінкування нічого не обмежує. Правило 7 вимагає обрізати розмір сторінки, якщо сторінкування є. Нульовий чи від'ємний `pageSize` теж не відхиляється.
- **Як виправити:** Додати константу, напр. `MAX_PAGE_SIZE = 100`, і писати `const size = Math.min(Math.max(1, Math.trunc(pageSize) || 20), MAX_PAGE_SIZE);`. Повертати фактичний `size`.
