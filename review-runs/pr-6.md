F1 · critical · блокує · Правило 3 — ім'я файлу від завантажувача потрапляє у readFile без нормалізації й перевірки теки

- Де: app/src/imports.js:18
- Що: const text = await readFile(path.join(uploadDir, fileName), "utf8");. Тут немає path.resolve і немає перевірки, що шлях лишився в uploads/. path.join сам розкриває .., тому path.join("/srv/uploads", "../../etc/passwd") дає /etc/passwd. За PR.md, fileName — це «ім'я, з яким його завантажили», тобто його обирає той, хто надсилає файл. Крім того, uploadDir — публічний параметр ({ uploadDir = UPLOAD_DIR } = {}, рядок 16), тож будь-який викликач може підставити довільну теку.
- Наслідок: громада надсилає файл з іменем ../../config/secrets.env (на Windows і ..\..\…). Адміністратор запускає імпорт, і функція читає довільний файл сервера поза uploads/. Кожен рядок після першого стає «учасником», а текст до першої коми потрапляє в name. Далі цей вміст бачить увесь персонал через listMembers.
- Як виправити:
const base = path.resolve(UPLOAD_DIR);
const target = path.resolve(base, fileName);
if (path.dirname(target) !== base) throw new AccessDenied();
  Прибрати uploadDir з публічних опцій або перевіряти його так само. Для тестів краще задавати теку через конфігурацію, а не через аргумент виклику. Додати тест assert.rejects(importMembersFromUpload(db, admin, "../x.csv", …), AccessDenied).
