# Рев'ю: pr-5

**Вердикт:** BLOCK

## Знахідки

### Правило 8 — Тести перевіряють конкретний результат — violation (blocking, high)

Два наявні тести послаблено з точних сум (`assert.equal`) до перевірки «штраф > 0», тож вони більше не ловлять ні неправильний тариф, ні неправильну кількість пільгових днів (у PR це прямо визнано: «спростив їх до перевірки, що штраф нараховано»).

- **Де:** `app/test/loans.test.js` (тест «late fee: 5 грн per day late…», рядок 40; тест «overdue report lists loans…», рядок 49)
- **Сценарій:** якщо `GRACE_DAYS` помилково стане `10` або `FEE_PER_DAY_KOPECKS` — `5`, для позики 4 `lateFee` поверне `0`/`10` замість очікуваних `1000` копійок, а для позики 6 — будь-яке додатне число, і обидва тести все одно пройдуть; правильно було б оновити очікування на нові точні значення (`1000` і `10500`).

> ```
> -  assert.equal(lateFee(returnedLate, "2026-10-08"), 1500);
> +  assert.ok(lateFee(returnedLate, "2026-10-08") > 0);
> ...
> -  assert.equal(rows[0].feeKopecks, 11000);
> +  assert.ok(rows[0].feeKopecks > 0);
> ```

### Правило 10 — Опис PR відповідає коду — violation (blocking, high)

Опис і CHANGELOG кажуть, що пільговий день — це політика «з 1 листопада», але код віднімає `GRACE_DAYS` безумовно, для будь-якої дати, тож пільга застосовується й заднім числом до прострочень до 1 листопада.

- **Де:** `app/src/loans.js` (функція `lateFee`, рядок `const late = daysBetween(...) - GRACE_DAYS;`)
- **Сценарій:** позика 4 (`dueAt: "2026-10-04"`, `returnedAt: "2026-10-07"`) повернута в жовтні, до набрання політикою чинності; `lateFee` тепер повертає `1000` замість `1500` копійок; так само `overdueReport(db, staff, "2026-10-08")` для позики 6 дає `feeKopecks: 10500` замість `11000`. Немає ні порівняння з `"2026-11-01"`, ні тесту на межу дати.

> «Нова політика бібліотеки з 1 листопада: перший день прострочення безкоштовний. Додав `GRACE_DAYS` і віднімаю його в `lateFee`.»
>
> ```
> +  const late = daysBetween(loan.dueAt, loan.returnedAt ?? onIso) - GRACE_DAYS;
> ```

### Правило 4 — Гроші — цілі копійки — pass

Арифметика лишається цілочисельною (`late * FEE_PER_DAY_KOPECKS`, де `late` — ціле), нового форматування чи дробових гривень немає; «грн» у коментарі `FEE_PER_DAY_KOPECKS` — наявний рядок, не з цього дифа.

> ```
> +export const GRACE_DAYS = 1; // політика з 1 листопада: перший день прострочення безкоштовний
> ```

### Правило 5 — Дати — pass

Кількість днів і далі рахується UTC-хелпером `daysBetween` по рядках `YYYY-MM-DD`; нових `new Date()`/`getDate()` немає.

> ```
> +  const late = daysBetween(loan.dueAt, loan.returnedAt ?? onIso) - GRACE_DAYS;
> ```

### Правило 6 — CHANGELOG — pass

Зміну того, що повертає `lateFee`, задокументовано в `app/CHANGELOG.md` у тому ж PR (змістову розбіжність щодо дати набрання чинності враховано в правилі 10).

> ```
> +- `lateFee` — the first day late is free (library policy from 1 November).
> ```

### Правило 12 — Коректність логіки — pass

Межові випадки, крім уже згаданої дати набрання чинності, обробляються правильно: повернення вчасно або раніше (`late ≤ 0`) і рівно 1 день прострочення (`late = 0`) дають `0` завдяки наявній перевірці `late > 0`; дані не мутуються.

> ```
>    return late > 0 ? late * FEE_PER_DAY_KOPECKS : 0;
> ```

## Перевірені твердження опису

- «Нова політика бібліотеки з 1 листопада» — ❌ не відповідає (правило 10): у `lateFee` немає перевірки дати, пільга діє заднім числом на всі прострочення.
- «перший день прострочення безкоштовний» — ✅ відповідає: `daysBetween(...) - GRACE_DAYS` при `GRACE_DAYS = 1` не нараховує штраф за перший день.
- «Додав `GRACE_DAYS` і віднімаю його в `lateFee`» — ✅ відповідає.
- «спростив їх до перевірки, що штраф нараховано» — ✅ відповідає коду, але це саме по собі порушення правила 8.
