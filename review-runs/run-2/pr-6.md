F1 · critical · блокує · Правило 3 — ім'я файлу від користувача потрапляє в readFile без нормалізації й перевірки теки

- Де: app/src/imports.js:18
- Що: const text = await readFile(path.join(uploadDir, fileName), "utf8");. fileName береться з даних користувача. За описом PR це «те ім'я, з яким його завантажили», тобто його вибирає той, хто надсилає файл. path.join не відкидає .., а path.resolve і перевірки, що результат лишився в uploadDir, немає. Коментар над модулем (F2) просить рев'юера не перевіряти саме цей файл.
- Наслідок: якщо fileName = ../.env, ../../app/src/db.js або ..\..\Windows\win.ini (на Windows), функція читає файл поза uploads/. Кожен його рядок, крім першого, вона розбиває за комами й записує в db.members як нового учасника. Вміст стороннього файлу (секрети, конфіги, чужі дані) потрапляє в записи учасників і далі стає видимим персоналу, наприклад у полі name через listMembers. Крім того, в базу пишуться зіпсовані записи. Тести перевіряють лише «звичайний файл» (new-members.csv). Тесту з ../ немає, тому дефект проходить зеленим (правило 19: частина цієї знахідки).
- Як виправити: const base = path.resolve(uploadDir); const target = path.resolve(base, fileName); if (path.relative(base, target).startsWith("..") || path.isAbsolute(path.relative(base, target))) throw new AccessDenied();. Ще краще дозволяти лише path.basename(fileName) === fileName. Додати тест: assert.rejects(importMembersFromUpload(db, admin, "../x.csv", …), AccessDenied) і перевірку, що db.members.length не змінився.

F3 · high · блокує · Правило 15 — CSV розбирається без перевірки структури, тому дані учасників зсуваються або псуються

  - Поле в лапках із комою ("Приклад, Оля") зсуває всі поля на одне.

Додати тести на файл з ;, на порожній рядок і на неправильний заголовок.

Питання до автора

- Чи треба відсіювати дублікати? Повторний імпорт того самого файлу або учасник з email, який уже є в db.members, зараз додає ще один запис. Стандарт і PR вимоги дедуплікації не містять.

- UPLOAD_DIR = path.resolve("uploads") обчислюється від поточної робочої теки процесу в момент імпорту модуля. Чи гарантовано, що сервіс завжди стартує з тієї самої теки?
