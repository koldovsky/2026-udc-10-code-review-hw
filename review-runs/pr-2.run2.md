## Що заявляє PR
Додає email учасника в кожен рядок staff-only звіту `overdueReport`.
- «для кожного рядка беремо учасника і віддаємо ім'я та email»
- «Звіт і так лише для персоналу, тож email тут доречний»

## Знахідки

### 1. [high] [R2, R8] Email віддається без запису в журнал доступу; тест цього не перевіряє
- **Де:** `app/src/loans.js:+55` (диф, рядок 16); `app/test/loans.test.js:+48` (диф, рядок 32)
- **Цитата:** `email: db.findMember(l.memberId)?.email ?? null,`
- **Чому це проблема:** домовленість 2 — кожна функція, що повертає email, пише `logAccess` по одному запису на учасника. З дифом: `overdueReport(db, librarian, "2026-10-08")` віддає 3 email, `db.accessLog.length === 0`. Те, що звіт лише для персоналу, — нормально (email персоналу бачити можна); дефект саме у відсутності сліду в журналі, як у сусідньої `memberCard`. Новий тест перевіряє `rows[0].email`, але не журнал.
- **Як виправити:** для кожного унікального `memberId` у результаті — `logAccess(db, user, memberId, "overdue-report")`; тест на вміст `db.accessLog`.
- **Впевненість:** висока

### 2. [medium] [R19] Мапу `id → ім'я` замінено на лінійний пошук двічі на кожен рядок
- **Де:** `app/src/loans.js` (диф, рядки 9, 15–16)
- **Цитата:** `-  const names = new Map(db.members.map((m) => [m.id, m.name]));` → `member: db.findMember(l.memberId)?.name ?? "—",` / `email: db.findMember(l.memberId)?.email ?? null,`
- **Чому це проблема:** `findMember` — `members.find(...)`, O(учасники). Звіт стає O(позики × учасники). Перевірено з дифом: на 2 003 прострочених позиках — 4 006 викликів `findMember` (кожен — лінійний прохід по учасниках). Позики й учасники ростуть без меж.
- **Як виправити:** повернути `Map` за id: `const byId = new Map(db.members.map((m) => [m.id, m]));` і `const m = byId.get(l.memberId);` один раз на рядок.
- **Впевненість:** висока

### 3. [medium] [R4, R10] `feeText` — гроші, відформатовані для людей у `src/`, і зміна, якої немає в описі
- **Де:** `app/src/loans.js:+59` (диф, рядок 20)
- **Цитата:** `feeText: (lateFee(l, todayIso) / 100).toFixed(2).replace(".", ",") + " грн",`
- **Чому це проблема:** домовленість 4 — у API лише цілі копійки, форматує клієнт. З дифом: `feeText: "110,00 грн"`. Опис цього поля не згадує («віддаємо ім'я та email»).
- **Як виправити:** прибрати `feeText`; клієнт форматує `feeKopecks`.
- **Впевненість:** висока

### 4. [low] [R6] Зміна формату відповіді без запису в `app/CHANGELOG.md`
- **Де:** `app/CHANGELOG.md` у дифі не змінено
- **Цитата:** `email: …`, `feeText: …`
- **Чому це проблема:** `overdueReport` повертає нові поля — це зміна контракту (домовленість 6). Блокує за домовленістю; серйозність low — ловиться CI-перевіркою.
- **Як виправити:** запис: «`overdueReport` додає `email`; кожен учасник у звіті записується в журнал доступу».
- **Впевненість:** висока
