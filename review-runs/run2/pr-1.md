## Знахідки

### 1. [high] Off-by-one: сторінка 1 пропускає перші `pageSize` записів — правило 15 (також 10)
- **Де:** `app/src/loans.js:32`
- **Цитата:**
  ```js
  export function listLoansPage(db, user, { page = 1, pageSize = 20 } = {}) {
    const all = listLoans(db, user);
    const start = page * pageSize;
  ```
- **Чому це проблема:** `page` за замовчуванням дорівнює 1, тобто нумерація з одиниці, а зміщення рахується як `page * pageSize`. Тому сторінка 1 починається з 20-го запису, і перші 20 позик недоступні жодним `page ≥ 1`. На тестовій БД (7 позик) виклик `{ page: 1, pageSize: 20 }` повертає `items: []` при `total: 7`. Крім того, `page: 0` чи від'ємне значення ніхто не перевіряє: `page = -1` дає `slice(-20, 0)`, тобто `[]`, а нечисловий `page` дає `NaN` і теж порожню сторінку без помилки.
- **Як виправити:** `const start = (page - 1) * pageSize;`, а `page` перед цим перевірити: це ціле ≥ 1, інакше кидати помилку або приводити до 1.

### 2. [high] Розмір сторінки від клієнта не обрізається — правило 7
- **Де:** `app/src/loans.js:30`
- **Цитата:**
  ```js
  export function listLoansPage(db, user, { page = 1, pageSize = 20 } = {}) {
  ...
    return { items: all.slice(start, start + pageSize), page, pageSize, total: all.length };
  ```
- **Чому це проблема:** список позик росте без меж (уже 3 000+ рядків) і йде в інтерактивний UI. Клієнт може передати `pageSize: 1e9` і отримати весь список за раз, тобто сторінкування нічого не обмежує. Також `pageSize ≤ 0` чи `NaN` тихо повертають порожню сторінку.
- **Як виправити:** ввести константу, наприклад `MAX_PAGE_SIZE = 100`, і нормалізувати значення: `const size = Math.min(Math.max(1, Math.trunc(pageSize) || 20), MAX_PAGE_SIZE);`. У відповідь повертати саме обрізаний `size`.
