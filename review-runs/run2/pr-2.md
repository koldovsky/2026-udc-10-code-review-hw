# Рев'ю PR-2: Email учасника у звіті про прострочення

## Знахідки

### 1. Звіт віддає email учасників, але не пише їх у журнал доступу
- Правило: #2 — функція, що повертає email чи телефон, викликає `logAccess` на кожного учасника
- Рівень: блокує
- Впевненість: висока
- Де: `review-queue/pr-2/change.diff:16` (`app/src/loans.js:54` після зміни)
- Доказ: `+      email: db.findMember(l.memberId)?.email ?? null,`
- Чому це проблема: тепер `overdueReport` віддає персональні дані (email) усіх боржників, але в ньому немає жодного виклику `logAccess`. У `loans.js` навіть немає імпорту з `./audit.js`. Сусідній `memberCard` (`app/src/members.js:16`) пише `logAccess(db, user, m.id, "member-card")` перед тим, як віддати email. Те, що звіт доступний лише персоналу (див. `PR.md:4-5`), не скасовує журнал: `memberCard` для персоналу теж пише запис.
- Що зробити: імпортувати `logAccess` і для кожного учасника, чий email потрапив у результат, писати `logAccess(db, user, memberId, "overdue-report")`. Це один запис на учасника, а не один на весь звіт. Додати тест, що після виклику `db.accessLog` містить запис для кожного `memberId` у звіті.

### 2. У `src/` форматуються гроші: дробові гривні, `toFixed`, рядок «грн»
- Правило: #4 — гроші в API лише цілими копійками, форматування робить клієнт
- Рівень: блокує
- Впевненість: висока
- Де: `review-queue/pr-2/change.diff:20` (`app/src/loans.js:58` після зміни)
- Доказ: `+      feeText: (lateFee(l, todayIso) / 100).toFixed(2).replace(".", ",") + " грн",`
- Чому це проблема: правило прямо забороняє `toFixed` і рядки з «грн» у `src/`. Форматувати має клієнт, бо API віддає лише `feeKopecks`.
- Що зробити: прибрати поле `feeText`. Клієнт форматує суму з `feeKopecks`.

### 3. Індекс `Map` замінено лінійним пошуком усередині циклу, складність стала O(n×m)
- Правило: #17 — зміна не погіршує складність
- Рівень: блокує
- Впевненість: висока
- Де: `review-queue/pr-2/change.diff:9`, `:15`, `:16` (`app/src/loans.js:53-54` після зміни; `db.findMember` у `app/src/db.js:41-43`)
- Доказ: `-  const names = new Map(db.members.map((m) => [m.id, m.name]));` → `+      member: db.findMember(l.memberId)?.name ?? "—",` і `+      email: db.findMember(l.memberId)?.email ?? null,`
- Чому це проблема: `findMember` робить `members.find(...)`, тобто лінійний пошук. PR прибирає наявний індекс і викликає цей пошук двічі на кожен рядок у `.map` по позиках. Стандарт окремо виділяє саме цей випадок: «заміна наявного індексу на пошук у циклі».
- Що зробити: залишити індекс, наприклад `const members = new Map(db.members.map((m) => [m.id, m]));`, і брати `members.get(l.memberId)` один раз на рядок.

### 4. `CHANGELOG.md` не оновлено, хоча змінилась форма результату `overdueReport`
- Правило: #6 — зміна того, що публічна функція повертає, записується в `app/CHANGELOG.md` у тому самому PR
- Рівень: блокує
- Впевненість: висока
- Де: `app/CHANGELOG.md:8-9`. Диф цей файл не змінює.
- Доказ: у CHANGELOG `` `overdueReport(db, user, todayIso)` — staff-only report of loans past due, with `loanId`, `member`, `book`, `daysLate`, `feeKopecks`. ``, а диф додає поля `email` (`change.diff:16`) і `feeText` (`change.diff:20`).
- Чому це проблема: у результат додано нові поля, а запису про це немає. Наявний запис тепер не відповідає фактичній формі результату.
- Що зробити: додати запис у `app/CHANGELOG.md` про нове поле `email` (`string | null`) у рядках `overdueReport` і про те, що функція пише в журнал доступу. `feeText` не документувати, а прибрати (див. знахідку 2).

### 5. Опис PR не згадує нове поле `feeText` і заміну індексу
- Правило: #10 — опис PR відповідає коду
- Рівень: блокує
- Впевненість: висока
- Де: `review-queue/pr-2/PR.md:3-5` і `review-queue/pr-2/change.diff:9`, `:20`
- Доказ: опис каже лише `«Тепер для кожного рядка беремо учасника і віддаємо ім'я та email»`, а код додає ще `+      feeText: ... + " грн",` і видаляє `const names = new Map(...)`.
- Чому це проблема: про дві зміни поведінки опис мовчить: новий текстовий формат суми і прибраний індекс. Рев'юер і споживачі API про них не дізнаються з опису. Твердження «звіт і так лише для персоналу» правдиве (`requireRole(user, STAFF)` у `app/src/loans.js:48`), але воно не обґрунтовує, чому немає журналу доступу.
- Що зробити: прибрати `feeText` або описати його в PR.md. Згадати, як шукається учасник і що email тепер пишеться в журнал доступу.

### 6. Учасника і пеню рахують двічі на рядок, docstring застарів
- Правило: #14 — назви, дублювання, читабельність
- Рівень: дрібниця
- Впевненість: висока
- Де: `review-queue/pr-2/change.diff:15-16`, `:19-20`. Docstring: `app/src/loans.js:43-46`.
- Доказ: `db.findMember(l.memberId)` викликано двічі, `lateFee(l, todayIso)` викликано двічі. У docstring: `with the member's name. Built for the weekly reminder calls.`
- Чому це проблема: однаковий виклик повторюється в одному виразі. Docstring досі каже, що звіт віддає лише ім'я, хоча тепер там ще й email.
- Що зробити: обчислювати учасника і пеню один раз на рядок (у тілі `.map` з `{ ... return }`). Оновити docstring: звіт віддає email і пише в журнал доступу.
