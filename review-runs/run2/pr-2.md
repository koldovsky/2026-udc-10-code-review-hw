## Знахідки

### 1. [critical] Email учасників повертається без запису в журнал доступу — правило 2 (також 10)
- **Де:** `app/src/loans.js:54`
- **Цитата:**
  ```js
        email: db.findMember(l.memberId)?.email ?? null,
  ```
- **Чому це проблема:** `overdueReport` тепер повертає email кожного боржника, але ніде не викликає `logAccess`. Сусідня `memberCard` (`app/src/members.js:16`) записує кожне читання. Тут же персонал отримує email багатьох учасників за раз, і в `db.accessLog` не лишається жодного запису. На питання «хто і навіщо дивився мої дані» відповісти неможливо. Опис PR виправдовує зміну тим, що звіт для персоналу. Але правило 2 від ролі не залежить.
- **Як виправити:** імпортувати `logAccess` з `./audit.js`. Викликати `logAccess(db, user, memberId, "overdue-report")` по одному разу на кожного **унікального** учасника, чий email потрапив у звіт. Учасників, яких не знайдено (`email === null`), пропускати. Додати тест: після `overdueReport(createDb(), iryna, "2026-10-08")` в `accessLog` є записи для memberId 1, 2 і 5 з `by: 3`.

### 2. [high] Сума форматується в `src/` (`/100`, `toFixed`, «грн»), і в описі PR цього поля немає — правило 4 (також 10)
- **Де:** `app/src/loans.js:58`
- **Цитата:**
  ```js
        feeText: (lateFee(l, todayIso) / 100).toFixed(2).replace(".", ",") + " грн",
  ```
- **Чому це проблема:** домовленість 4 вимагає, щоб гроші в API йшли лише цілими копійками, а форматування для людей робив клієнт. Тут `src/` ділить на 100, викликає `toFixed` і віддає рядок із валютою. Крім того, `PR.md` описує лише ім'я та email, тобто поле `feeText` додано непомітно, поза заявленим обсягом.
- **Як виправити:** прибрати `feeText`. Клієнт форматує суму з `feeKopecks`.

### 3. [high] Нових полів у поверненні `overdueReport` немає в CHANGELOG — правило 6
- **Де:** `app/CHANGELOG.md (немає в дифі)`
- **Цитата:**
  ```js
  +      email: db.findMember(l.memberId)?.email ?? null,
  ...
  +      feeText: (lateFee(l, todayIso) / 100).toFixed(2).replace(".", ",") + " грн",
  ```
- **Чому це проблема:** публічна функція тепер повертає нові поля `email` і `feeText`. Проте в CHANGELOG `overdueReport` досі описано з полями `loanId`, `member`, `book`, `daysLate`, `feeKopecks`, а сам `app/CHANGELOG.md` у PR не змінювався.
- **Як виправити:** додати запис на кшталт «`overdueReport` returns `email` per row; each listed member's read is recorded in the access log». Поле `feeText` не описувати, а прибрати (див. #2).

### 4. [medium] Індекс `Map` замінено на лінійний пошук, двічі на кожен рядок — правило 15
- **Де:** `app/src/loans.js:53`
- **Цитата:**
  ```js
  -  const names = new Map(db.members.map((m) => [m.id, m.name]));
  ...
  +      member: db.findMember(l.memberId)?.name ?? "—",
  +      email: db.findMember(l.memberId)?.email ?? null,
  ```
- **Чому це проблема:** `db.findMember` — це `members.find(...)` (`app/src/db.js:42`). Раніше мапа будувалася один раз, а тепер на кожну прострочену позику йдуть два лінійні пошуки. Виходить O(позик × учасників), і обидва списки ростуть без меж. Це регресія складності порівняно з наявним індексом.
- **Як виправити:** лишити одну мапу `new Map(db.members.map((m) => [m.id, m]))`, і в кожному рядку один раз брати `const m = byId.get(l.memberId)`.
