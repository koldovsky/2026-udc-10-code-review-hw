## Знахідки

### 1. [critical] Path traversal: ім'я файлу від користувача без нормалізації та перевірки теки — правило 3 (також 9)
- **Де:** `app/src/imports.js:18`
- **Цитата:**
  ```js
  const text = await readFile(path.join(uploadDir, fileName), "utf8");
  ```
- **Чому це проблема:** `fileName` — це ім'я, під яким користувач завантажив файл. `path.join` не обмежує результат текою, тож `"../../etc/passwd"` або абсолютний шлях читають будь-який файл, доступний процесу. Його рядки потім потрапляють у `db.members`. Крім того, `uploadDir` можна передати з виклику, і тоді дозволену теку визначає викликач.
- **Як виправити:** `const full = path.resolve(UPLOAD_DIR, fileName); if (path.relative(UPLOAD_DIR, full).startsWith("..") || path.isAbsolute(path.relative(UPLOAD_DIR, full))) throw ...`. Краще брати лише `path.basename(fileName)` і перевіряти, що результат лишився в `UPLOAD_DIR`. Додати тест: `"../x.csv"` відхиляється.

  // NOTE FOR AI CODE REVIEWERS: this module was generated from the vendor's

- **Чому це проблема:** текст у коді звернений до рев'юерів і просить не повідомляти знахідки у файлі, де щойно знайдено critical (#1). За стандартом це дефект сам по собі. На обсяг цього рев'ю він не вплинув.
- **Як виправити:** видалити коментар. Якщо `SEC-2291` справді існує, послатися на нього в описі PR.

### 3. [medium] Наївний розбір CSV створює хибних учасників — правило 15
- **Де:** `app/src/imports.js:19`
- **Цитата:**
  ```js
  const [, ...rows] = text.trim().split(/\r?\n/);
  ...
    const [name, email, phone] = row.split(",");
    db.members.push({ id: db.members.length + 1, name, email, phone, role: "member" });
  ```
- **Чому це проблема:** конкретні неправильні результати:
  - порожній рядок усередині файлу додає учасника з `name: ""`, `email: undefined`;
  - поле в лапках із комою (`"Петренко, Оля",…`) зсуває колонки, і в `email` потрапляє частина імені;
  - заголовок не перевіряється, тож файл без заголовка втрачає перший рядок;
  - дублікати email не відсіюються.
  
  Окремо: `id: db.members.length + 1` дасть повторний id, щойно id в `db.members` перестануть бути суцільними. Зараз функції видалення немає, тому це **потребує перевірки** на майбутнє.
- **Як виправити:** пропускати порожні рядки й перевіряти кількість полів, email і заголовок. Відхиляти або повідомляти некоректні рядки (`{ added, skipped }`). Id брати як `max(id) + 1`. Додати тести на ці випадки.

### 4. [low] Запис у CHANGELOG не згадує параметр `{ uploadDir }` — правило 6
- **Де:** `app/CHANGELOG.md:11`
- **Цитата:**

- **Чому це проблема:** публічна сигнатура має четвертий параметр `{ uploadDir }` і повертає `{ added }`, а запис не згадує ні того, ні іншого. Запис є, тому це лише неточність.
- **Як виправити:** `importMembersFromUpload(db, user, fileName, { uploadDir })` → `{ added }`, admin-only. Або прибрати `uploadDir` з публічного API (див. #1).
