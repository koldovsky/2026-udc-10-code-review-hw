Додає `listLoansPage` — сторінковий варіант списку позик для персоналу (сторінка, розмір сторінки, загальна кількість), не змінюючи `listLoans`.

## Знахідки

### 1. [high] [R15] Сторінка 1 пропускає перші `pageSize` записів (off-by-one)
- **Де:** `app/src/loans.js:+31` (диф, рядки 10–12)
- **Цитата:** `export function listLoansPage(db, user, { page = 1, pageSize = 20 } = {}) {` … `const start = page * pageSize;`
- **Чому це проблема:** сторінки нумеруються з 1 (дефолт `page = 1`), але зсув рахується як для нумерації з 0. Перевірено з застосованим дифом: `listLoansPage(db, librarian, { page: 1, pageSize: 3 })` → id `[4, 5, 6]` замість `[1, 2, 3]`; `{ page: 1, pageSize: 20 }` при 7 позиках → `items: []`. Тобто виклик за замовчуванням повертає порожню сторінку, а перша сторінка даних недоступна взагалі.
- **Як виправити:** `const start = (page - 1) * pageSize;` і тест, що перевіряє саме `items` на першій і на останній сторінці.
- **Впевненість:** висока

### 2. [high] [R7] Розмір сторінки не обмежено зверху, вхід не валідовано
- **Де:** `app/src/loans.js:+31-34` (диф, рядки 10–13)
- **Цитата:** `{ page = 1, pageSize = 20 } = {}` … `all.slice(start, start + pageSize)`
- **Чому це проблема:** клієнт може передати `pageSize: 1e6` (після виправлення off-by-one — отримати весь список за раз), тобто сторінкування не захищає від проблеми, заради якої PR створено. `page: 0`, від'ємні чи дробові значення, `NaN` теж не відхиляються — `slice` з від'ємним `start` повертає хвіст списку.
- **Як виправити:** `MAX_PAGE_SIZE` (напр. 100) і `pageSize = Math.min(pageSize, MAX_PAGE_SIZE)`; перевірка `Number.isInteger(page) && page >= 1`, `Number.isInteger(pageSize) && pageSize >= 1`, інакше помилка.
- **Впевненість:** висока

### 3. [high] [R8] Новий тест не перевіряє результат — лише відлунює вхідні параметри
- **Де:** `app/test/loans.test.js:+15-20` (диф, рядки 36–41)
- **Цитата:** `assert.equal(res.total, 7);` `assert.equal(res.page, 1);` `assert.equal(res.pageSize, 20);`
- **Чому це проблема:** `page` і `pageSize` просто повертаються з аргументів, `total` — довжина повного списку. Тест жодного разу не дивиться на `items`, тому зелений при порожній сторінці (знахідка 1). Це саме «функція щось повернула», а не перевірка конкретного результату.
- **Як виправити:** `assert.deepEqual(res.items.map((l) => l.id), [1, 2, 3])` для `{ page: 1, pageSize: 3 }`, остання неповна сторінка, сторінка за межами, а також перевірка, що учасник на сторінках бачить лише свої позики.
- **Впевненість:** висока

### 4. [high] [R6] Нова публічна функція без запису в `app/CHANGELOG.md`
- **Де:** `app/src/loans.js:+30` (диф, рядок 10); `app/CHANGELOG.md` у дифі не змінено
- **Цитата:** `export function listLoansPage(db, user, { page = 1, pageSize = 20 } = {}) {`
- **Чому це проблема:** домовленість 6: «Нова функція — теж зміна» і потребує запису в тому самому PR. Клієнти UI не дізнаються про контракт `{ items, page, pageSize, total }` і нумерацію сторінок.
- **Як виправити:** додати запис, напр. `listLoansPage(db, user, { page, pageSize })` → `{ items, page, pageSize, total }`, сторінки з 1, `pageSize ≤ 100`.
- **Впевненість:** висока

### 5. [medium] [R9] Немає тесту на відхилений доступ для нової функції
- **Де:** `app/test/loans.test.js` (диф, рядки 36–41)
- **Цитата:** `const res = listLoansPage(createDb(), iryna, { page: 1, pageSize: 20 });`
- **Чому це проблема:** функція покладається на перевірку в `listLoans` (`if (!user) throw new Error("user required")`) і фільтр «учасник бачить лише свої». Жоден тест не фіксує, що без користувача виклик відхиляється і що учасник не бачить чужих позик через сторінковий варіант — регресію в делегуванні ніхто не помітить.
- **Як виправити:** тест `assert.throws(() => listLoansPage(createDb(), null), …)` і тест для `olya`, що `total === 3` і всі `items` мають `memberId === 1`.
- **Впевненість:** середня

### 6. [medium] [R10/R7] Опис: «для персоналу», але функція не staff-only; `listLoans` лишається безмежним
- **Де:** `app/src/loans.js:+29` (диф, рядок 9); PR.md
- **Цитата:** `/** Paged variant for the staff UI: { items, page, pageSize, total }. */`
- **Чому це проблема:** коментар і опис кажуть «для персоналу», а код доступний будь-якому користувачеві (з фільтром на власні позики). Поведінка узгоджена з `listLoans`, тож це радше неточність опису/коментаря. Окремо: старий `listLoans` на 3 000+ рядків лишається публічним і безмежним (R7) — варто зафіксувати план міграції UI або позначити його deprecated у CHANGELOG.
- **Як виправити:** виправити коментар («staff see all, members see their own») і додати в CHANGELOG примітку про `listLoans`.
- **Впевненість:** середня

### 7. [low] [R15] Сторінка будується з копії всього списку
- **Де:** `app/src/loans.js:+32` (диф, рядок 11)
- **Цитата:** `const all = listLoans(db, user);`
- **Чому це проблема:** `listLoans` копіює всі 3 000+ рядків (`rows.map((l) => ({ ...l }))`) на кожен запит сторінки — для in-memory некритично, але суперечить меті PR («усе гальмує»).
- **Як виправити:** фільтрувати, різати `slice`, а копіювати лише рядки сторінки.
- **Впевненість:** середня
