Знахідки

F1 · high · блокує · Правило 15 — перша сторінка пропускає перші pageSize позик (off-by-one)

- Де: app/src/loans.js:32
- Що: За замовчуванням page = 1, тобто сторінки рахуються з 1. Але зсув обчислюється як для нумерації з 0: const start = page * pageSize;. Тому page: 1 повертає all.slice(20, 40) замість all.slice(0, 20).
- Наслідок: Бібліотекарка відкриває список позик і бачить сторінку 1 ({ page: 1, pageSize: 20 }). Перших 20 позик вона не побачить ніколи, ні на якій сторінці. На тестовій базі (7 позик) items для сторінки 1 порожній ([]), хоча total: 7. Список вигляда порожнім, а «загальна кількість» йому суперечить.
- Як виправити: const start = (page - 1) * pageSize;. Додати тест, що сторінка 1 повертає перші записи, а сторінка 2 — наступні (див. F4).

F2 · high · блокує · Правило 7 — розмір сторінки не обмежено максимумом, page/pageSize не перевіряються

- Де: app/src/loans.js:30-33
- Що: { page = 1, pageSize = 20 } приймаються як є. Максимуму немає, тож pageSize: 1_000_000 повертає всі 3 000+ рядків за раз. Немає й перевірки, що значення цілі й додатні. Від'ємний page дає від'ємний start, і slice бере записи з кінця списку. Дробові значення (page: 1.5) дають зсув, якого не передбачено.
- Наслідок: Будь-який клієнт UI чи API одним запитом з великим pageSize знову тягне весь список. Тобто проблема, яку PR мав розв'язати, лишається. Некоректні page повертають випадкові «сторінки» без помилки.
- Як виправити: Додати константу максимуму (наприклад, MAX_PAGE_SIZE = 100) і обрізати до неї pageSize. Для нецілих значень і значень < 1 кидати помилку або нормалізувати їх. Покрити це тестами.

F3 · high · блокує · Правило 6 — нова публічна функція без запису в CHANGELOG

- Де: app/src/loans.js:30 (export function listLoansPage(...)). У дифі немає змін app/CHANGELOG.md.
- Що: З'являється нова export-функція listLoansPage(db, user, { page, pageSize }), яка повертає { items, page, pageSize, total }. app/CHANGELOG.md у PR не змінено.
- Наслідок: Споживачі API не знають про нову функцію, формат її параметрів (зокрема, з якого числа рахуються сторінки) і формат результату. CI-перевірка з правила 6 впаде.
- Як виправити: Додати запис у app/CHANGELOG.md: сигнатура, нумерація сторінок, обмеження pageSize, формат результату.

F4 · medium · блокує · Правило 8 — тест не перевіряє вміст сторінки

- Де: app/test/loans.test.js:15-20
- Що: Тест перевіряє лише res.total, res.page і res.pageSize. Два останні — просто вхідні параметри, які функція повертає назад. res.items не перевіряється зовсім. Тест проходить, хоча items порожній (F1).
- Наслідок: Тест дає хибне відчуття покриття. Головну поведінку функції (які саме записи на сторінці) не перевірено, тому дефект F1 пройшов би CI.
