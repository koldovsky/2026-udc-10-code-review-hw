## Знахідки

### 1. [high] Off-by-one: `page = 1` пропускає першу сторінку — правило 15 (також 10)
- **Де:** `app/src/loans.js:32`
- **Цитата:**
  ```js
  export function listLoansPage(db, user, { page = 1, pageSize = 20 } = {}) {
    const all = listLoans(db, user);
    const start = page * pageSize;
  ```
- **Чому це проблема:** За замовчуванням нумерація сторінок іде з 1 (`page = 1`), але зсув рахується як для нумерації з 0. На `page=1` повертаються рядки 20–39, тож перші 20 позик через цей API отримати неможливо. З тестовими даними (7 позик) `page=1` взагалі дає порожній `items`. Від'ємні або дробові `page` теж не перевіряються, а `slice` з від'ємним початком повертає рядки з кінця списку.
- **Як виправити:** `const start = (page - 1) * pageSize;`. Перед цим перевірити, що `page` — ціле число ≥ 1 (`Number.isInteger(page) && page >= 1`), інакше кидати помилку або зводити до 1.

### 2. [high] Розмір сторінки не обмежено зверху — правило 7 (також 15)
- **Де:** `app/src/loans.js:30`
- **Цитата:**
  ```js
  export function listLoansPage(db, user, { page = 1, pageSize = 20 } = {}) {
    ...
    return { items: all.slice(start, start + pageSize), page, pageSize, total: all.length };
  ```
- **Чому це проблема:** Клієнт може передати `pageSize: 1e9` і отримати весь список одним запитом. Правило вимагає обмеженого максимального розміру сторінки, а ліміт від клієнта має обрізатися. `pageSize` ≤ 0 або дробовий теж не перевіряється. У відповіді функція повертає `pageSize` у тому вигляді, як його передали, а не той, що реально застосовано.
- **Як виправити:** Додати константу, наприклад `MAX_PAGE_SIZE = 100`, і обрізати: `const size = Math.min(Math.max(1, Math.trunc(pageSize) || 20), MAX_PAGE_SIZE);`. У відповіді повертати `pageSize: size`.

- **Де:** `app/CHANGELOG.md (немає в дифі)`
- **Цитата:**
  ```js
  +export function listLoansPage(db, user, { page = 1, pageSize = 20 } = {}) {
  ```
- **Чому це проблема:** Новий `export` у `src/` — це зміна публічного API. Конвенція 6 прямо вимагає запису в `app/CHANGELOG.md` у тому самому PR.
- **Як виправити:** Додати рядок, наприклад: `` `listLoansPage(db, user, { page, pageSize })` — paged loans list: `{ items, page, pageSize, total }`; pages start at 1, `pageSize` capped at N. ``

### 4. [high] Тест не перевіряє вміст сторінки й тому пропустив off-by-one — правило 8
- **Де:** `app/test/loans.test.js:15`
- **Цитата:**
  ```js
  test("paged list reports the total and the page it returned", () => {
    const res = listLoansPage(createDb(), iryna, { page: 1, pageSize: 20 });
    assert.equal(res.total, 7);
    assert.equal(res.page, 1);
    assert.equal(res.pageSize, 20);
  });
  ```
- **Чому це проблема:** Тест перевіряє лише `total` і два параметри, які функція просто повертає назад. `items` не перевіряються взагалі, тому тест проходить, хоча на `page=1` повертається порожній масив (див. #1).
- **Як виправити:** Перевірити конкретні id. Наприклад, `listLoansPage(db, iryna, { page: 1, pageSize: 3 }).items.map(l => l.id)` має дорівнювати першим трьом id; на `page: 3` має лишитися одна позика. Окремо перевірити, що завеликий `pageSize` обрізається до максимуму.

### 5. [medium] Немає тесту на відмову: учасник не має бачити чужих позик через сторінки — правило 9
- **Де:** `app/test/loans.test.js:15`
- **Цитата:**
  ```js
  const res = listLoansPage(createDb(), iryna, { page: 1, pageSize: 20 });
  ```
- **Чому це проблема:** `listLoansPage` фільтрує за власником (через `listLoans`), але тестується лише з користувачем-персоналом. Немає тесту, що учасник отримує тільки свої позики і правильний `total`, і немає тесту на виклик без користувача. Якщо `listLoansPage` колись перепишуть без делегування в `listLoans`, тести цього не помітять.
- **Як виправити:** Додати тест: `listLoansPage(createDb(), olya, { page: 1, pageSize: 20 })` має повернути `items` з id `[1, 2, 7]` і `total === 3`. Додати також `assert.throws(() => listLoansPage(createDb(), null), /user required/)`.
