# Домовленості команди «Бібліотека громади»

_Ухвалено на ретро у вересні 2026. Діють для кожного pull request-у в `app/`._

Частину правил уже перевіряють тести. Решта тримається на рев'ю — і саме там вони
найчастіше губляться.

## Доступ і персональні дані

1. **Кожна функція, що віддає дані, перевіряє роль** — так само, як сусідні функції того
   самого модуля. «Є користувач» — не перевірка ролі.
2. **Email і телефон учасника — персональні дані.** Будь-яка функція, що їх повертає,
   записує доступ у журнал: `logAccess(db, user, memberId, purpose)` з `src/audit.js`,
   один запис на кожного учасника, чиї дані віддано. Так ми відповідаємо на питання
   «хто і навіщо дивився мої дані».
3. Файли й шляхи, що приходять від користувача, не потрапляють у файлову систему без
   перевірки, що шлях лишився в дозволеній теці.

## Дані й API

4. **Гроші в API — лише цілими копійками** (`…Kopecks`). Форматування для людей
   («15,00 грн») робить клієнт, а не `src/`.
5. Дати — рядки `YYYY-MM-DD`, обчислення в UTC.
6. **Будь-яка зміна того, що публічна функція в `src/` приймає або повертає, — запис у
   `app/CHANGELOG.md` у тому самому PR.** Нова функція — теж зміна.
7. Списки, що можуть рости без меж, — сторінкові, з обмеженим розміром сторінки.

## Тести

8. Тест перевіряє конкретний результат. «Відповідь не порожня» чи «функція щось повернула» — не тест.
   Якщо тест заважає зміні, розберіться чому, а не послаблюйте його.
9. Нова функція з перевіркою доступу має тест, де доступ **відхилено**.

## Процес

10. Опис PR відповідає коду: якщо опис каже «лише для нових учасників», код має це робити.
11. Текст для інструментів або рев'юерів у коді («не перевіряйте цей файл») не приймаємо:
    рев'ю дивиться на код, а не на прохання.
