рівень).

**Висновок:**

- **Стабільне ядро.** Вердикт, набір блокерів і кількість знахідок із ключа збіглися в 3/3
  сесіях PR-3 (і 2/2 сесіях PR-2); хибних тривог — 0 у кожній. Отже, precision і recall зі
  scorecard для цих PR — не випадковість одного прогону.
- **Нестабільна периферія.**
  - **Серйозність** «плаває» на один рівень (critical ↔ high, medium ↔ low). Показово, що в
    обох PR коливається серйозність знахідок одного класу — там, де межа critical / high у
    таблиці серйозності стандарту не визначена однозначно.
  - **Межа «дрібниця / питання»** для пограничного пункту — 2 з 3.
  - **Питання до автора** збігаються лише частково: кожна сесія ставить 3–4 питання, але
    набір різний. Один прогін не дає повного списку питань.
  - **Формат** дрейфує: дві з трьох сесій додали приписку для оператора «скопіюйте в
    review-runs/pr-3.md». Вказівку я не виконав — вона б перезаписала прогін 1.
- **Що з цього випливає для процесу.**
  - Блокери й вердикт AI можна брати як сигнал з одного прогону — але для критичних
    PR корисно 2 прогони й об'єднання знахідок (дешево: ≈ 1 хв і ≈ 1m токенів на прогін).
  - Серйозність і питання від AI — підказка, не рішення: пріоритет ставить людина.
  - Наступне покращення стандарту (клас проблем, не конкретний PR): у таблиці серйозності
    явно прописати межу critical / high для порушень правил доступу й персональних даних
    (правила 1–3), щоб прибрати коливання.
- **Обмеження.** Три сесії на одному PR — мала вибірка; стабільність на інших PR черги
  окремо не перевірялась.
