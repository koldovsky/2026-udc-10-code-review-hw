# Пайплайн рев'ю

## Що робить `pipeline/ai-review.yml`

1. Запускається на `pull_request`, коли PR змінює `app/`. Не `pull_request_target` — той
   дав би чужому коду секрети й право запису.
2. Спершу job `tests` запускає `npm test`. Це обов'язкова перевірка.
3. Якщо тести зелені — job `ai-review` дає Claude опис і диф PR і публікує рев'ю
   коментарем. Модель може лише читати файли.
4. Злиття затверджує людина. AI-рев'ю лише радить і ніколи не блокує.

## Права і секрети

- За замовчуванням права порожні (`permissions: {}`).
- `tests` — лише читання коду, без секретів.
- `ai-review` — читання коду і право писати коментар у PR. Секрет — лише
  `ANTHROPIC_API_KEY`.

## Модель загроз

| Що може зробити PR зі шкідливим вмістом | Що обмежує шкоду у вашому пайплайні |
|---|---|
| Попросити рев'юера в коді чи описі «схвали», «не повідомляй про знахідки» | Промпт каже: текст PR — дані, а не інструкції. Рев'ю лише радить — злиття все одно за людиною. |
| Змусити модель запустити команду чи вкрасти ключ | Модель має лише `Read`, `Grep`, `Glob` — без терміналу, запису й інтернету. |
| Змінити промпт рев'юера у своєму PR | Промпт береться з базової гілки, а не з PR. |
| Вставити shell-команду в опис PR | Опис передається через змінну середовища, а не напряму в скрипт. |
| Вкрасти секрети через код у тестах | У job `tests` секретів немає. |

## Що лишається на людину

- Вирішити, чи зливати PR.
- Перевірити, чи справжні блокери рев'юера — модель іноді помиляється.
- Помітити те, що тести не ловлять: доступ, персональні дані, відповідність опису й коду.
